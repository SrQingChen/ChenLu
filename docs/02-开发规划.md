# 尘露 · 开发规划

> 前置阅读：[01-调研报告.md](01-调研报告.md)。本文档给出技术选型、模块化架构、核心设计、功能分期、里程碑与风险对策，作为项目实施的基准蓝图。

---

## 一、产品定位与原则

**一句话定位**：免费、无广告、无会员的现代 Android 自动化连点器——以 Shizuku 特权注入引擎做到「最快、最稳、最难被检测」，以无障碍引擎做到「零门槛开箱即用」，以「尘露岛」做到澎湃 OS 3 级的交互质感。

**设计原则**：

1. **双引擎分层**：无障碍引擎是默认保底（零门槛、全场景），Shizuku 引擎是增强档（高频、防检测）；运行时可一键切换、故障自动降级。
2. **引擎无关的任务模型**：所有功能（录制、预设、十字准星、图色触发）都编译为统一的任务 IR，由调度器分发到任一引擎执行——保证可扩展性（未来可插拔 HID、Root、ADB-over-network 引擎）。
3. **诚实的能力标注**：频率、多点并行能力按引擎如实展示实测值，不做"1000 次/秒"式虚假宣传（竞品差评重灾区）。
4. **权限最小化 + 渐进式引导**：每个权限在使用时才申请，图形化引导页逐项带跳转（尤其 HyperOS 保活三件套与 Shizuku 配对）。
5. **免费开源**（GPL-3.0），无广告、无会员、无云强制。

## 四、核心设计

### 4.1 引擎抽象（engine/api）

```kotlin
interface InputEngine {
    val descriptor: EngineDescriptor          // id、名称、能力、状态流
    val capabilities: EngineCapabilities      // maxTapHz(实测)、multiTouchMax、supportsPressure、latencyMs…
    val state: StateFlow<EngineState>         // Ready / Degraded(原因) / Unavailable(引导动作)

    suspend fun tap(point: PointF, spec: TapSpec)            // 单击（含按压时长/压力）
    suspend fun swipe(stroke: StrokeSpec)                    // 滑动/曲线（关键点插值）
    suspend fun multiTouch(strokes: List<StrokeSpec>)        // 多指同步（≤capabilities 上限）
    suspend fun rawInject(events: List<MotionEventSpec>)     // 低级事件序列（回放用）
    suspend fun cancel()                                     // 立即中止（抬指所有触点）
}

data class TapSpec(val durationMs: Long = 50, val pressure: Float = 1f)
data class StrokeSpec(
    val points: List<TimedPoint>,            // 轨迹关键点（时间+坐标）
    val pointerId: Int = 0,
    val source: TouchSource = TouchSource.TOUCHSCREEN,
)
```

- **EngineRegistry** 按优先级（用户偏好 → 能力匹配 → 可用性）解析出 `activeEngine`；Shizuku binder 死亡 → 自动降级无障碍并通知用户（尘露岛弹出提示）。
- 频率上限由 `capabilities.maxTapHz` 驱动 UI 滑杆范围，**以实测基准为准**（M1 里程碑产出真机基准数据）。

### 4.2 Shizuku 引擎（engine/shizuku + core/shizuku）

**AIDL（运行在 Shizuku server 侧、shell 身份的 UserService 内）**：

```aidl
interface IChenLuInjector {
    void destroy() = 16777114;               // Shizuku 保留事务码
    void tap(in MotionEventSpec event);       // 或用 Parcel 化自定义事件包
    void injectAll(in List<MotionEventSpec> events, int mode);  // mode: ASYNC/WAIT_FOR_RESULT/WAIT_FOR_FINISH
    void cancelAll();
    long ping();
}
```

实现要点（全部来自已核实的官方模式）：

- `UserService` 以 `@Keep` 标注防混淆；`Shizuku.UserServiceArgs(componentName).tag("injector").version(code)` 显式 tag；`destroy()` 中清理并 `System.exit(0)`。
- UserService 进程不受非 SDK 限制，直接 `InputManager.getInstance().injectInputEvent(MotionEvent.obtain(...), 2)`，事件构造（DOWN/MOVE/UP、多指 pointerId、压力、SOURCE_TOUCHSCREEN）在 domain 层生成 `MotionEventSpec`（可序列化），跨进程传输后原样注入。
- App 侧 `core/shizuku` 负责：binder sticky 监听、权限三段式、 UserService 重连（版本不匹配自动 destroy 旧实例）、**激活引导**（检测未安装 Shizuku → 跳转下载；binder 死亡 → 拉起 `moe.shizuku.privileged.api` 主界面一键重启，因第三方无法直接拉起 server，已核实）。
- 兼容 Sui（root 用户零成本同 API）、预留 Dhizuku。

### 4.3 任务模型与调度器（domain/task）

```kotlin
@Serializable
data class Task(
    val id: Long, val name: String,
    val steps: List<Step>,
    val loop: LoopSpec = LoopSpec(count = 1),          // 次数/无限/时长/直到触发停止
    val jitter: JitterSpec = JitterSpec(),             // 随机坐标偏移±n px、时序抖动±n ms
    val stopCondition: StopCondition? = null,          // 图色条件停止/通知停止/热区外停止
)

@Serializable
sealed interface Step {
    @Serializable data class Click(val point: PointF, val spec: TapSpec = TapSpec()) : Step
    @Serializable data class Swipe(val stroke: StrokeSpec) : Step
    @Serializable data class MultiTouch(val strokes: List<StrokeSpec>) : Step
    @Serializable data class Wait(val durationMs: Long) : Step
    @Serializable data class Repeat(val steps: List<Step>, val count: Int) : Step   // 嵌套循环
    @Serializable data class IfColor(val rule: ColorRule, val thenSteps: List<Step>, val elseSteps: List<Step> = emptyList()) : Step
}

@Serializable
data class ColorRule(
    val samples: List<ColorSample>,                  // 多点比色（offset+color+threshold），对齐社区习惯
    val region: RectF? = null,                       // 区域找色时
    val mode: MatchMode = MatchMode.ALL_POINTS,      // ALL_POINTS / REGION_FIND / REGION_NOT_FOUND
)
```

- **Scheduler**：把 `Task` 展开为带时间戳的事件流，逐段喂给引擎；注入 `JitterSpec` 随机化；支持暂停/恢复/单步/倍速。
- **TriggerEngine**（domain/trigger）：订阅 `ScreenSource` 帧流，对注册的 `ColorRule` 求值（`matcher` 模块，位图采样 + 阈值比较，纯 Kotlin），命中后执行动作（启动/停止/切换任务），支持边沿触发与防抖。

### 4.4 屏幕感知（vision 层）

```kotlin
interface ScreenSource {
    val frames: SharedFlow<Frame>            // Frame: Bitmap/Buffer + 时间戳 + 分辨率
    suspend fun requestAccess(): Boolean     // 授权流程（各实现不同）
    fun release()
}
```

- **主通道 MediaProjection**：授权流（Android 14+ 先用户同意→再启动 `mediaProjection` FGS，顺序严格）；VirtualDisplay + ImageReader 复用帧（按需缩放到监听区域，降低开销）；用于 ≥10Hz 的实时图色。
- **兜底通道无障碍 takeScreenshot**（API 30+）：≈3FPS，只服务低频规则，免二次授权（已开无障碍即用）。
- 引导文案明确 Android 14+ 每次会话需确认的系统行为；Android 15+ 状态栏共享指示条属系统预期，文档说明。

### 4.5 岛体系（IslandPublisher）与悬浮窗体系：原生超级岛优先，传统通知栏兜底

**IslandPublisher（岛发布器）**——统一接口、多实现按可用性自动降级：

```kotlin
interface IslandPublisher {
    val availability: StateFlow<IslandAvailability>  // Available(通道) / Degraded(原因) / Unavailable
    suspend fun publish(state: TaskRuntimeState)     // 任务名/状态/进度/频率/计数 + 启停控制
    suspend fun dismiss()
}
```

| 实现 | 机制 | 定位 |
|---|---|---|
| MediaIslandPublisher | MediaSession + MediaStyle 通知（Android 14+ 声明 `mediaPlayback` FGS 类型）→ 官方"媒体通知自动上岛"，**免审核**；title=任务名、subtitle=状态文本、进度条=任务进度、播放/暂停按钮=连点启停 | 次选：Focus 不可用或兼容模式关闭时的合规原生形态（HyperOS 3 自动展示） |
| FocusIslandPublisher | extras `miui.focus.param`（V3 模板：大小岛、胶囊进度环、AOD；business 用任务进度类模板）；「兼容模式」——经 Shizuku 临时断 `com.xiaomi.xmsf` 网络令云端鉴权 fail-open（MAA-Meow 式：随 Shizuku 就绪**默认启用**、副作用透明告知+一键关、结束自动恢复、断网状态落盘兜底）。JSON 构建参考 HyperNotification 库结构（引入前确认其许可证，不兼容则自建 builder） | **首选（能用就用）**：OS3 焦点岛全形态 |
| OverlayIslandPublisher | 自绘「尘露岛」胶囊（见下表） | 可选增强（后期版本）：全安卓通用、视觉对标，**不进默认链路** |
| NotificationFallback | 常驻通知 + `Notification.Action`（进度 + 启停/切换模式按钮） | **默认兜底**：传统通知栏，简单可靠、零额外权限 |

可用性探测（`notification_focus_protocol ≥ 3`、岛硬件特性、用户"焦点通知"开关）驱动默认降级链：**Focus → Media → Notification**（原生超级岛能用就用，兜底走传统通知栏）；自绘「尘露岛」不进默认链路，作为后期可选视觉增强，用户可在设置中手动启用替换 Notification 层。

| 悬浮组件 | 形态 | 技术 |
|---|---|---|
| **尘露岛（自绘·可选增强）** | 顶部胶囊：任务名/频率/计数；点击展开控制面板（开始/暂停/换任务/引擎徽章）；按官方设计规范（pId=2142/2143 的摘要态/展开态尺寸与动效曲线）对标 | TYPE_APPLICATION_OVERLAY + View 体系胶囊壳 + Compose 面板（ViewTreeLifecycleOwner 三件套注入）；弹簧动效 |
| **十字准星** | 可拖拽小准星；**按住即按设定频率在准星处连点，松手即停**；按压触发与拖动移动以拖动阈值区分手势 | 纯 View 自绘（onDraw 十字+脉冲环），不依赖 Compose（轻量、低延迟） |
| **控制球** | 收纳态拖拽球（悬浮窗总入口），双击展开岛 | View + 拖拽吸附边缘 |
| **录制标记** | 录制时的点位回放浮层 | View 自绘 |

状态切换入口（用户要求的"悬浮超级岛或下滑通知栏切换"）：**岛面板（原生岛 Action / 自绘岛按钮）、常驻通知 `Notification.Action`、TileService 磁贴**三路等价，共享同一个 `AutomationController`（StateFlow 单一事实源）。

十字准星状态机：`Hidden → Shown(模式开启) → Armed(按下开始连点) → Drag(移动) → Shown`；触发条件与频率来自该模式的预设。

### 4.6 录制三档（feature/recorder）

1. **Shizuku getevent 录制**（有 Shizuku 时，最高保真）：UserService 内读 `/dev/input` 解析多点触控原始事件流（shell 可读）→ 时序 IR。
2. **无障碍触摸观察**（API 34+）：`AccessibilityService` 观察触摸事件序列。
3. **手动可视化编排**（全版本兜底）：屏幕上直接添加/拖拽点位、连线编排滑动、设置间隔——所见即所得编辑器。
录制产物统一为 `Task`，可再编辑；回放叠加 `JitterSpec` 防检测（竞品空白点）。

### 4.7 保活与引导（feature/onboarding）

- `AutomationService`：FGS 声明 `specialUse`（subtype 文案：自动化任务执行引擎），常驻通知即控制面。
- 引导页分步检测并带跳转：无障碍开启（含 Android 13+ "允许受限设置"路径）、悬浮窗（MIUI 独立开关）、通知、忽略电池优化、HyperOS 三件套（省电无限制/自启动/锁后台）、Shizuku 配对向导（内置图文+常见坑提示：安全设置调试、原生通知样式）、原生岛可用性检测（焦点通知开关引导；兼容模式随 Shizuku 就绪默认启用并说明副作用，可一键关）。
- 全局"自检"页：权限矩阵 + 引擎状态 + 一键修复建议。

## 五、功能分期

### M0 — 工程骨架（约 2 周）
- 多模块工程 + convention plugins + version catalog + CI（构建、lint、单测、detekt）
- designsystem 主题与基础组件、导航框架、CI 产出 APK

### M1 — MVP「好用的基础连点器」（约 4–6 周）
- 无障碍引擎：单点/多点位序列点击、滑动、长按；频率/时长/次数配置
- 控制球 + 基础悬浮面板；常驻通知控制；TileService
- 任务库（Room：增删改查/导入导出 JSON）；预设模板 10+（游戏/抢购/办公场景）
- 引导页（权限自检）；HyperOS 保活引导
- **真机基准测试**：两引擎 tapHz 实测数据入库并展示（诚实频率的起点）

### M2 — Shizuku 引擎 + 动态十字准星（约 4–6 周）
> 进展：Shizuku 引擎已提前于 2026-09-20 落地（core:shizuku 手写 Binder 协议 + engine:shizuku + 引擎偏好切换），十字准星与尘露岛仍在 M2。
- core/shizuku + engine/shizuku：AIDL UserService、injectInputEvent、自动降级、激活向导
- **十字准星模式**：按住连点/松手停；IslandPublisher 上线（焦点岛优先 + 媒体岛 + 传统通知栏兜底）；三路状态切换（岛/通知/磁贴）
- 引擎切换 UI（能力对比卡片：频率/延迟/检测面）
- 性能：Shizuku 引擎实测基准（目标 ≥100Hz 稳定，实测为准）

### M3 — 录制回放 + 图色触发（约 4–5 周）

## 六、发布与更新分发（GitHub + Mirror酱）

**原则：GitHub Releases 是唯一事实源与永久免费主线路；Mirror酱（MirrorChyan）是国内 CDN 加速通道；GitHub 直连 + ghproxy 前缀兜底永远保留。**（调研详见 [01-调研报告.md](01-调研报告.md) 第六节）

### 6.1 发布管线（GitHub Actions）

```
tag 推送（v*）触发：
  构建（arm64-v8a 优先，R8 + 签名）→ 生成 sha256
  → 创建 GitHub Release（SemVer；stable/beta/alpha 通道由 tag 推断）
  → MirrorChyan/uploading-action@v1 转传 Mirror酱
     （filetype: latest-release、os: android、rid + upload_token 存 Secrets）
```

- **接入流程（联系制）**：Mirror酱集成 QQ 群 1026040805 申请 `rid` 与 `upload_token`（自助开启无效）；初审 3 个工作日、季度复查；GPL-3.0 满足其 OSI 许可证核查；无游戏绑定的连点器定位能否过审，接入前入群确认。
- Workflow 模板参考 MaaXYZ/MaaPracticeBoilerplate 的 `mirrorchyan_release.yml`（MIT）；MAA-Meow 更新模块（AGPL）只参考思路，尘露自研实现。
- 开发者侧接入免费且享下载分成（可按 MAA 模式反哺项目基建）。

### 6.2 应用内更新器（core/update 模块）

```kotlin
interface UpdateSource {
    suspend fun check(current: SemVer): UpdateInfo   // 版本/更新说明/下载计划/sha256/是否增量
}
// MirrorChyanSource（首选检查：无 CDK 也返回版本信息，国内连通性好）
// GitHubSource（releases/latest；下载前缀链：直连 → ghfast.top → gh-proxy.com 多前缀轮试）
```

- **检查顺序对齐 MAA-Meow/MXU 实践**：始终先打 Mirror酱 API（`GET /api/resources/{rid}/latest?current_version=…&os=android&arch=…&channel=stable&user_agent=ChenLu`），失败或无下载链接再走 GitHub + ghproxy 前缀链。
- **CDK（用户可选）**：设置页填写（¥6.9/月，一码通用 Mirror酱 全平台项目），本地加密存储、绝不写日志；无 CDK 不是错误——只是拿不到 CDN 直链，自动转 GitHub。
- **安装**：APK 落缓存目录 + sha256 校验 → FileProvider + `ACTION_VIEW` 拉起系统安装器（用户确认式，非静默）；声明 `REQUEST_INSTALL_PACKAGES` 并在引导页说明"未知来源应用"授权。侧载开源分发无合规问题；未来上架 Play/国内商店的版本移除内置更新器，开源版保留。
- 版本策略：SemVer + `-beta.N` 通道后缀；"仅 Wi-Fi 下载"开关；下载失败自动换前缀重试。

### 6.3 互补渠道矩阵

| 渠道 | 用途 | 备注 |
|---|---|---|
| GitHub Releases | 唯一事实源、永久免费主通道 | README 明示，永不牺牲 |
| Mirror酱 | 国内 CDN 加速 + 下载分成 | 无硬 SLA（个人/小团队基建），仅作加速层 |
| ghproxy 前缀链 | GitHub 直连失败兜底 | ghfast.top / gh-proxy.com，可自建（WJQSERVER-STUDIO/ghproxy） |
| IzzyOnDroid | 海外 FOSS 合规通道 | 需 APK ≤30MB + fastlane 元数据；Shizuku 本体在架佐证 |
| Gitee/GitCode | 代码只读镜像 | 新仓库人工审核，自动化题材易卡，不做分发 |
| 蒲公英（pgyer） | 封闭内测扫码分发 | 公开发布后撤下 |

## 七、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Shizuku 激活门槛劝退用户 | 高 | 无障碍引擎保底零门槛；Shizuku 向导图形化+常见坑内置；"不装 Shizuku 也能用全部基础功能"的明确定位 |
| Shizuku 重启失效 | 中 | binder 死亡监听→自动降级+通知引导一键重启；文档推荐 v13.6.0 受信任 WLAN 自动启动/插电自启方案 |
| 原生岛灰色通道失效/合规风险（xmsf fail-open 被小米修补；断网期间影响全机小米推送） | 中 | 兼容模式随 Shizuku 就绪默认启用（首次引导透明告知+一键关，结束自动恢复+落盘兜底）；fail-open 失效自动降级媒体岛→通知栏；跟踪小米侧动态 |
| HyperOS 杀后台/关无障碍 | 高 | 三件套引导 + FGS + 自检页；被杀后状态可恢复（任务持久化） |
| 游戏反作弊（高频机械点击特征） | 中 | Jitter 随机化默认可开；免责声明（遵守目标 App 条款）；不宣传"防封号" |
| Play/商店政策（干扰其他应用类） | 中 | 上架版本突出无障碍工具属性（isAccessibilityTool）、场景中性化描述；必要时 Play 版与开源版功能分级 |
| injectInputEvent 频率不达预期（工程估计未实测） | 低 | M2 首周即做真机基准；不达标则如实标注实际值，仍远超无障碍 |
| Android 17+ 无障碍政策收紧 | 中 | 引擎抽象已隔离；Shizuku/HID 引擎可插拔补位 |
| GPL 传染（参考 GPL 项目代码） | 低 | 只参考思路不复制代码；贡献者协议（CLA 可选）与依赖扫描进 CI |
| Mirror酱通道依赖（个人基建无硬 SLA；连点器题材过审不确定） | 中 | GitHub 主线路永远保留，Mirror酱仅加速层；发布前入群确认过审；被下架不影响 GitHub/ghproxy 下载 |
| 内置更新器的商店合规（REQUEST_INSTALL_PACKAGES 属受限权限） | 低 | 侧载开源版保留内置更新器；未来商店版移除自更新、走商店升级 |
